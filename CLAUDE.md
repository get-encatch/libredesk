# CLAUDE.md

This repo is **get-encatch/libredesk**, the Encatch (CMSS) fork of [abhinavxd/libredesk](https://github.com/abhinavxd/libredesk). The goal is to run a released libredesk version, add our own non-breaking features on top, and keep pulling upstream releases.

## Branches and remotes

- `origin` = get-encatch/libredesk (our fork). `upstream` = abhinavxd/libredesk.
- `release/v2.8.0` is an untouched copy of the upstream `v2.8.0` tag (`086b082`). Never commit our changes to `release/*` branches.
- Our integration branch is `encatch/main` (the default branch on GitHub), created from `release/v2.8.0`. Changes reach it only through pull requests (since 2026-10-10):
  - One branch per piece of work, from `encatch/main`: `feat/...`, `fix/...`, `chore/...`, or `merge/vX.Y.Z` for upstream releases.
  - Open a PR into `encatch/main`; the Go CI check (`test`) must pass. No review approval is required (single maintainer).
  - Merge with a merge commit; squash and rebase merges are switched off, so upstream merges keep their history.
  - Repository admins can bypass in an emergency; say so in the commit message if you do.
- `main` mirrors upstream `main`, which is unreleased code. Do not build from it or deploy it.
- Upstream releases are git tags (`vX.Y.Z`) cut from upstream `main`. There are no upstream release branches.

## Pulling upstream releases

- Merge **stable release tags only**, never upstream `main` or `-rc` tags:
  `git fetch upstream --tags && git switch -c merge/vX.Y.Z encatch/main && git merge vX.Y.Z`, then a PR into `encatch/main` merged with a merge commit

## Rules for our changes (to keep upstream merges easy)

- Prefer adding new files over editing upstream files. Put Encatch code in its own folders (e.g. `internal/encatch/` for the backend, a separate folder under `frontend/`). Keep the hooks into upstream code small and mark them with an `// encatch:` comment.
- Database: don't edit upstream `schema.sql` or the per-version migration files (`internal/migrations/v*.go`). Prefix our tables with `encatch_` and keep our migrations separate.
- Don't change existing upstream APIs, tables or columns. Add new ones instead.
- Consider sending generic fixes and hooks upstream as PRs, to reduce what we maintain ourselves.

## Releases and container images

- Images are published only to GitHub Container Registry: `ghcr.io/get-encatch/libredesk`, linux/amd64 only (tags `latest` and `vX.Y.Z-encatch.N`). There is no Docker Hub publishing.
- Release by tagging `encatch/main` as `vX.Y.Z-encatch.N`, where `X.Y.Z` is the upstream version we're based on, e.g. `v2.8.0-encatch.1`. Never reuse a plain upstream tag name.
- Pushing such a tag runs `.github/workflows/release.yml` (GoReleaser). It pushes the images and creates a **draft** GitHub Release that someone publishes by hand. Plain upstream tags (`vX.Y.Z`) don't trigger it.
- Deploys need no SSH: after the build, `.github/workflows/encatch-deploy.yml` waits for approval on the GitHub `production` environment (reviewer: godwinpinto; branch policy `encatch/main`), then records a GitHub deployment. The server's deploy agent (`deploy/agent/deploy_agent.py`, systemd `encatch-deploy.timer`, every 2 min) pulls it from the public API, deploys with backup + health check + automatic rollback, and reports via `/.well-known/encatch-deploy.json` on the desk domain. On success the workflow publishes the tag's draft GitHub Release (Latest only if it's the newest version). Runbook: `deploy/README.md` > Deploys. Agent tests: `python3 -m unittest deploy/agent/test_deploy_agent.py`.
- Our edits to `.goreleaser.yaml` and `release.yml` are marked `# encatch:`. Expect small conflicts there when merging upstream releases, and keep our version (GHCR only, `get-encatch` owner, the My Tickets build hooks, Node 22).
- Releases so far that matter here: `v2.8.0-encatch.10` (2026-10-11) switched My Tickets to the Vue app and added text formatting; `.11` fixed the reply placeholder; `.12` (2026-10-12) added Account > Password; `.13` (2026-10-16) changed My Tickets rate limits (below); `.14` (2026-10-17) pointed Caddy at `libredesk_app`; `.15` (2026-10-23) added auto-close and klauspost/compress 1.18.7. A quick production check after a deploy: `/.well-known/encatch-deploy.json` on the desk domain shows the version, and `https://support.encatch.com/my-tickets/login` (no token) should land on the app's "missing its sign-in token" message.

## GitHub repository security (set 2026-10-10)

- Rulesets: "Protect branches" (no force-push or deletion of `encatch/main`, `main`, `release/*`, no bypass); "Release tags: immutable" (`v*` tags can't be moved or deleted by anyone); "Release tags: who can create" (only org admins create `v*` tags); "encatch/main: changes through PRs with CI" (PR required, Go `test` check must pass, merge commits only, repository admins may bypass). Squash and rebase merges are also switched off in the repository settings, because the ruleset's admin bypass covers its merge-method rule too.
- E2E: `.github/workflows/encatch-e2e.yml` (ours; upstream's `frontend-ci.yml` stays untouched and only runs for upstream `main`) runs upstream's Cypress suite on PRs into `encatch/main` in parallel shards, skipping Markdown/`deploy/`/`docs/`-only changes. Shards and known upstream failures are listed in `.github/encatch-e2e-shards.py`, which fails if a spec is in no shard. Informational, not a required check (an unrelated agent-app spec can flake: rerun the failed shard). `ui/slaForm.cy.js` fails when run after other specs (also on untouched upstream v2.8.0) but passes alone, so it runs in its own shard (`ISOLATED`); recheck after merging v2.9.0. `KNOWN_UPSTREAM_FAILURES` (empty) is for specs that fail even alone: they warn instead of failing. Syncing upstream tags into the fork therefore needs an org admin.
- My Tickets web: `.github/workflows/encatch-mytickets-web.yml` runs the app's Vitest tests, builds it and checks that Go serves the build, on PRs and pushes that touch the app or `internal/encatch/mytickets/spa*.go`. Informational too; only the Go `test` check is required.
- Auto-merge is switched off in the repository settings, so PRs are merged by hand (`gh pr merge N --merge`) once `test` (and, for My Tickets changes, `web`) pass.
- GitHub can silently disable all workflows on this fork ("Workflows on this fork have been disabled" on the repo's Actions page) while the API still reports Actions as enabled. It happened before 2026-10-16 (nothing ran from 2026-10-12): no PR checks, releases or deploys. If a PR shows no checks, look at the Actions page and re-enable (repository admin); then push a fresh commit to start CI. Free: the repo is public.
- Production environment: reviewer godwinpinto only, branch `encatch/main` only, admins can't bypass.
- Actions: approval required for all outside contributors' workflows; only GitHub-owned, verified, and the listed actions (goreleaser, docker, crowdin) may run. A new third-party action must be added under Settings > Actions first.
- Secret scanning with push protection, Dependabot alerts and security updates, and private vulnerability reporting are on. Our policy is `.github/SECURITY.md` (GitHub shows it before upstream's root `SECURITY.md`, which stays untouched). Upstream's PR-welcome workflow is disabled in GitHub (not edited).

## Production deployment

- `deploy/` holds our production stack (installed in `/srv/libredesk` on the server, reached as `ssh encatch-helpdesk`; the address and login are kept out of this public repo, in each person's `~/.ssh/config`). Two domains: **desk.encatch.com** for agents (full app, libredesk Root URL) and **support.encatch.com** for customers (Caddy allowlist of customer paths; everything else shows a static page). New customer-facing features must be added to the support allowlist in `deploy/Caddyfile`. `deploy/README.md` is the runbook: install/update, backups, restore.
- Stack: our GHCR app image (version pinned via `LIBREDESK_VERSION` in the server's `.env`), `postgres:18-alpine` with pgBackRest, Redis, Caddy for HTTPS. Upstream's root `docker-compose.yml` is untouched and not used in production.
- Backups (decided 2026-10-09): pgBackRest weekly full, daily differential, 6-hourly incremental, continuous WAL, keep 5 fulls; nightly `pg_dump` for 7 days; uploads via restic every 6h for 31 days; monthly automated restore test. All on the same disk for now; object storage (pgBackRest `repo2`) is planned.
- Secrets (`.env`, `secrets/restic-password`) exist only on the server and are git-ignored. Never commit them.
- Extra sites (2026-10-17): Caddy imports `/etc/caddy/sites/*.caddy` (server folder `data/caddy/sites/`, kept across deploys) for other services on this server that aren't libredesk, e.g. `mail.encatch.com` (Listmonk, `/srv/listmonk`) and `internal-status.encatch.com` (Gatus monitoring with Zoho Cliq alerts, `/srv/gatus`, private login in Caddy; added 2026-10-22). GitBar was removed on 2026-10-22. Their files live only on the server; runbook: `deploy/README.md` > Extra sites and > Monitoring (Gatus).
- The `postgres` container needs `init: true`: without it, pgBackRest's async archive workers make Postgres (as PID 1) restart in a loop.
- Helpdesk data change made directly in the production DB (no admin UI exists for it): an `Urgent` row in `conversation_priorities`. If an upstream migration ever inserts its own priorities, check it doesn't clash. The reports chart's hard-coded priority list (`OverviewBarChart.vue`) was extended to include it.
- Support tiers, SLA policies and SLA automation rules are config-as-code in `deploy/helpdesk-config/` (`config.json` + `apply.py`, run via the libredesk API). All SLAs use business hours (desk default: IST office hours). The script owns every automation rule named `SLA…`. Teams must not get their own business hours or SLA policy (either overrides the tier SLAs).
- New-ticket alert (2026-10-12, `new_ticket_alert` in `config.json`): every `SLA new: …` rule ends with a Notify action to the agent **Notification Desk** (the notification-desk group mailbox, role Agent, no team so it's never assigned tickets, no password), so each new ticket alerts that group mailbox once. It has to be in the SLA rules: new-ticket rules are first-match, and a "Team assigned" rule doesn't fire because the team is assigned by automation (libredesk ignores update events caused by its own rules). Libredesk's Notify action only reaches agents, and agent notification emails carry no loop-prevention header, so never notify an address the Support inbox reads (support@): each alert would come back as a new ticket.
- Auto-close (2026-10-21, `auto_close` in `config.json`): tickets left *Waiting on customer* get an automated reminder after 72 hours and status *Auto-closing*, then an automated close message after 120 hours and *Resolved* (two time-trigger rules named `Auto-close: …`, owned by `apply.py`, which also creates missing statuses). Hours count from the agent's last reply (automated System replies don't reset it); any customer reply reopens the ticket and stops it. Time triggers run hourly and only see tickets created in the last 30 days (upstream). Messages have no `{{ }}` placeholders: libredesk renders them only in the emailed copy, so My Tickets and the agent app would show them raw. My Tickets maps *Auto-closing* to "Waiting on you" (`model.go`, and the list filter in `adapter.go`).
- Running `apply.py` needs the desk domain (`LIBREDESK_URL=https://desk.encatch.com`; the support domain blocks the admin API) and an API key. Without a key, the same changes can be made through a signed-in admin's browser session: snapshot every GET `apply.py` makes, run it offline against the snapshot to get the exact writes, check them, then send them with the `X-CSRFTOKEN` header (from the `csrf_token` cookie). That's how the alert was applied.
- Desk behaviour worth knowing: agents get emails only when a ticket is assigned to them, they're @mentioned, or an SLA alert fires (no "new ticket to the whole team" email, hence the alert above). A team inbox lists only the team's tickets not yet assigned to an agent. "Forgot password" matches the agent's email exactly (stored lowercase) and says "sent" either way. No default outgoing email template is set, so libredesk logs `error fetching default outgoing email template` and falls back to a plain layout (harmless). SLA badges in the inbox count calendar time to a business-hours deadline (135 business hours ≈ 21 calendar days). SSO and password sign-in are independent: signing in with SSO doesn't stop password sign-in, there's no setting to switch passwords off (an "SSO only" design was studied on 2026-10-16, not built).
- Caddy keeps no access logs, and libredesk's own rate limiter logs nothing. To see requests, switch Caddy's access log on for a few seconds through its admin API (`deploy/README.md` > Debugging). That found the 2026-10-16 incident: a client on a customer's office network re-fetching a My Tickets page ~55 times a second used up the shared per-address limit and blocked replies (fixed in `.13`).
- Never change the System agent's email from `System`: libredesk looks it up by that email and refuses to start without it. The agent edit form forces a valid email, so don't save System through it; use `./libredesk --set-system-user-password` for its password.

Org and project names are stored on each ticket when it's raised; every Support sign-in rewrites them on that org's tickets if they changed in Encatch (`SyncNames`), and My Tickets always shows the current project name. Each ticket from My Tickets gets the attribute `encatch_instance` and the tag `instance:<code>` (e.g. `instance:prod`, created when missing), added by the System agent just before the customer's first message so the inbox list still previews the customer's text. Rate limits (2026-10-16, after an office network was locked out): the My Tickets pages and their files aren't rate limited (served from memory); API calls are limited per signed-in session (`my_tickets.api_requests_per_minute`, default 120, `internal/encatch/mytickets/ratelimit.go`, counted in Redis under a hash of the session token), and calls without a session fall back to libredesk's per-address `rate_limit.public`; sign-in keeps `rate_limit.auth`. Every trip is logged as `my-tickets: rate limited` (by session or by masked address), at most once a minute per key, because libredesk's limiter logs nothing. The app shows a clear "Too many requests" message on any 429 and keeps the draft. Customers resolve their own tickets (2026-10-23): "Mark as resolved" in the ticket header (`web/src/components/ResolveButton.vue`, `POST /my-tickets/api/tickets/{ref}/resolve`, `APIResolve`), for customers with Manage access on tickets not already Resolved/Closed, with an optional note (max 1000 characters). `adapter.go` `ResolveByCustomer` uses libredesk's own actions as the System agent: a private note (who, and their note, HTML-escaped), `ApplyAction` set_status → Resolved, then `ApplyAction` notify → the assigned agent (gated per instance like other agent notifications). The customer's note never goes into the notification: libredesk renders Notify emails with `text/template`, unescaped. Replying reopens the ticket, as before. Customer attachments are stored like agent uploads (private media, signed links) and must pass both libredesk's upload settings and `my_tickets.allowed_extensions`, with `my_tickets.max_total_upload_mb` (50) for all files of one message. `app.server.max_body_size` is set above 5 × libredesk's per-file limit so oversized uploads get a friendly message instead of a bare 413; raise it if that limit goes up.

Change password: agents change their own password at Account > Password (`frontend/apps/main/src/features/encatch/password/`, `PUT /api/v1/encatch/me/password` in `cmd/encatch_password.go`, behind the `auth` rate limit). It needs the current password and upstream's password rules (`rules.js` mirrors `IsStrongPassword`), and records upstream's `agent_password_set` activity. Upstream v2.8.0 has no self-service form, only an admin setting the password or "Forgot password". Agents who sign in with SSO don't know their random libredesk password, so it's for password sign-ins. Other sessions of the agent stay signed in.

Customer organisations (support tiers): `internal/encatch/orgtiers/` (tables `encatch_orgs` and `encatch_org_tier_changes`, created at startup), `cmd/encatch_orgs.go` (routes `/api/v1/encatch/orgs...`, all `sla:manage`) and `frontend/apps/main/src/features/encatch/orgs/`. An org is listed when its users first open Support (My Tickets login), or an admin adds it by hand. Its tier (default `SaaS Standard`, choices from `my_tickets.tiers`) goes on each new ticket as `ticket_tier`, which the SLA rules use; changing it affects new tickets only, and every change is logged with who made it.

Redaction ("Remove for security"): `internal/encatch/redact/` (all logic), `cmd/encatch_redact.go` (routes `/api/v1/encatch/...`, libredesk auth and conversation-access checks) and `frontend/apps/main/src/features/encatch/redact/` (menu + dialog). Agents can remove text or files from their own messages, admins from any message including customers'. A reason of at least 5 words is required and every removal is logged in our table `encatch_redactions` (created at startup by `redact.EnsureSchema`, `CREATE TABLE IF NOT EXISTS`; not an upstream migration) and in a private note. Admins (anyone with `activity_logs:manage`) browse and search the log at Admin > Teammates > Removal log (`GET /api/v1/encatch/redactions`). Files are deleted at once; a background job also purges files of deleted private notes immediately, relying on upstream's `delete-private-message` query setting `media.model_id = 0` (check this still holds when merging upstream). Text redaction stores the placeholder as `content_type = 'text'` because the agent app's HTML renderer doesn't re-render in place.
